# 自行车铃后续实验：验证改善不等于独立测试达标

2026-11-02。**尚未完成新独立测试验证，不宣布训练目标达成，不部署、不合并。** 本文接续首轮 [报告](EXPERIMENT-REPORT.zh-CN.md)，不改写首轮失败结果。所有代码、真实模型和记录仍在 `research/bicycle-bell-transfer-20261102` / [PR #47](https://github.com/ky0o0/traffic-sound-guardian-v1/pull/47)。V1.6.15 和原始 `yamnet.tflite` 保持不变。

## 核查与首轮失败原因

已读取首轮脚本、协议、数据 manifest、训练轨迹、锁定选择、测试结果及模型权重。逐一核验原 20 个产物 SHA-256，Actions 再执行原 `verify_results.py`。没有重复执行首轮六模型训练。复用原特征缓存前核对开发集逐录音原音频 SHA-256，缓存中旧测试数组未载入；旧测试音频未进入后续训练、验证或阈值选择。只读取旧测试元数据以排除相同 ID、上传者、字节和标准化 PCM 指纹。

首轮最终阈值选择明确要求 **Precision≥90%、FPR≤2%**，与当前 **FPR<5% 下优先召回** 的目标不同。高阈值倾向牺牲召回。首轮真正正例训练量只有 54 段、32 个上传者，验证 24 段中 19 段来自一位作者；测试也有来源集中。这支持阈值目标不匹配及新来源泛化不足的解释，不能仅凭现有结果断言具体声学根因。首轮低分漏报和高分金属敲击误报也说明只调阈值不能保证达标。

另发现一个数值边界问题：原验证边界分数约 `0.7501617074`，折入标准化参数后的保存头使用 NumPy 计算为 `0.7501615882`，差约 `1.19e-7`，严格 `>=` 会使一个验证样本变号。因此后续按实际算术结果报告固定阈值的 19/24，而不篡改首轮预折入参数验证记录的 20/24。该微小误差解释不了首轮测试 15 次漏报。今后锁定前必须用导出推理接口重新校准，并把阈值放在相邻验证分数之间、检查数值裕量。

## 新来源审查与第三轮

额外通过独立 Actions 访问 Wikimedia Commons、Freesound、Internet Archive，保存逐来源响应与错误。当地环境对这三类音频站／Hugging Face 返回网络策略 403，因此下载和训练实际在 GitHub Actions 标准 CPU runner 上执行；未绕过网络策略。新来源审查确认远程 runner 能访问这些服务，不能把本地 403 误写为所有数据不可获取。

Commons 多数明确车铃录音是首轮 Freesound 音频的转载，上传者与原 manifest 重叠，不能算新来源。结果中还混有朗读／访谈，不能将搜索命中直接当作铃声真值。Freesound 前五页获得 41 个未用上传者／ID 候选，29 个候选许可符合 CC0／CC BY；再按标题明确车铃并排除手机合成提示音，留下 26 段、25 位上传者。选取完全在任何模型打分之前完成。原始网页带有第三方令牌，首次推送被 GitHub secret scanning 拒绝；已改为仅保存必要元数据，没有解除推送保护。

[候选许可、上传者和预览地址](results/source-discovery/new-freesound-metadata.json) 均保留。这些是**上传者标题弱标签**，没有独立逐段听审；不得冒充 FSD50K 的人工审核标签，更不能直接作为最终可靠测试真值。预览是有损 MP3，需计入来源／编码分布变化。

第三轮用固定作者哈希分配新增来源，17 段用于训练、4 段用于验证、5 段封存为将来最终测试候选；同一作者不得跨集合。封存 5 段未下载、未推理，不使用成绩决定保留与否。这里的“封存”不表示已完成内容去重与听审，最终验收前仍须核查。

实际执行 [Actions 41445850349](https://github.com/ky0o0/traffic-sound-guardian-v1/actions/runs/41445850349)，新增正例与训练环境音做 10/20dB SNR 混合，增强只用于训练，混合样本不能算新的独立录音。所有对照仍使用同一推理窗口、步长和片段池化。第三轮在更丰富的同一个开发验证集上比较，不能将其与第二轮不同验证集的数字直接当作提升幅度。

## 停止边界与不可宣称的指标

本次计算资源可用，不能把 CPU 不足作为停止理由。限制在于可靠、足够多且尚未用于模型选择的独立测试数据：当前只封存了 5 位新作者的 5 段候选正例，没有独立听审，亦尚未建立与所有开发来源隔离且经过听审的最终困难负例集合。继续重复同一验证集调参无法解决这一证据缺口。因而本次自动执行在真实训练与开发验证后停止，不假装后台仍在训练，也不将 95.83% 的开发召回宣布为训练目标达成。

即使 5 段全部检出，按独立伯努利试验计算，零漏报时 FNR 的单侧 95% 上限仍约 **45.1%**；零失败时至少 59 个真正独立试验才使该上限低于 5%，而现实中多段录音常共享铃体／会话，不能把窗口数当作独立试验数。这个样本量说明不是修改用户目标，成功仍要求同一固定策略在新独立测试上同时 FNR<5%、FPR<5%。当前没有足够证据作该结论。

继续研究应优先扩大新来源并完成人工独立听审／标签验收，按上传者、录音会话、实体铃及内容重复分组，封存足够正／负样本；所有模型与阈值在开发集锁定并校验导出推理后，才进行一次最终测试。不能根据那个最终测试继续调参；失败后必须保留失败记录并另备最终数据。新候选公开音频仍可取得，未声称已经穷尽互联网上所有车铃。

未执行新的最终测试，因此本报告没有新的最终 TP/FP/FN/TN、FNR/FPR/Recall/Precision/F1；表格仅为真实开发验证。未有可靠事件起止、连续背景时间轴和真实设备测量，所以事件级召回、事件延迟、每小时误报均记为**未评估**，不得由片段指标换算。没有浏览器、iPad Safari、麦克风通路或交通安全可靠性验证。现有骨干微调所需更可靠的多来源数据不足，当前不以继续扩大参数搜索替代数据验收。
